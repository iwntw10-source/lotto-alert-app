# 릴리스 서명 · 빌드 가이드 (복권 알림이)

> 작성일 2026-09-21 · 앱 `com.lottoalert.app`
> 코드 쪽 준비는 끝나 있습니다. **키스토어 생성(비밀번호 설정)만 본인이 직접** 하시면 됩니다.

## 지금 상태

- `android/app/build.gradle`이 `android/keystore.properties`를 읽어서 릴리스 빌드에 자동으로 서명합니다.
  그 파일이 없으면 **서명 없이** 빌드됩니다 (이미 `bundleRelease` 성공 확인: 약 21MB).
- 키스토어와 비밀번호 파일은 `.gitignore`에 등록돼 있어 git에 올라가지 않습니다.
- 릴리스 빌드에는 디버그 전용 코드(`DebugRunReceiver`)와 정확한 알람 권한이 **들어가지 않는 것**을 확인했습니다.

---

## ⚡ 가장 쉬운 방법 — 스크립트 한 번 (1~3단계를 자동으로)

PowerShell에서 아래 한 줄을 실행하고, 물어보면 **비밀번호만 직접 입력**하세요 (영문/숫자/`!@#^*_+.~-`, 8자 이상, 공백·따옴표 금지).

```powershell
cd C:\Users\jski1\lotto-app-build
powershell -ExecutionPolicy Bypass -File tools\make-keystore-and-build.ps1
```

키 생성 → `keystore.properties` 작성 → AAB 빌드 → 서명 확인 → **`Downloads\lotto-alert-v1-release.aab`로 복사**까지 해 줍니다.
비밀번호는 화면에도 기록에도 남지 않고 `android\keystore.properties`(git 제외)에만 저장됩니다.
이미 키가 있으면 덮어쓰지 않고 그대로 씁니다. (건강 앱의 `app-release.aab`와 파일명이 달라 헷갈리지 않습니다.)

> 아래 1~3단계는 스크립트가 하는 일을 손으로 하는 방법입니다.

---

## 1단계 · 키스토어 만들기 (본인이 직접 — 비밀번호는 본인만 알아야 합니다)

PowerShell을 열고 프로젝트 폴더에서 실행합니다.

```powershell
cd C:\Users\jski1\lotto-app-build
& "C:\Users\jski1\.jdks\jbr-21.0.11\bin\keytool.exe" -genkeypair -v `
  -keystore android\upload-keystore.jks -alias upload `
  -keyalg RSA -keysize 2048 -validity 10000
```

물어보는 것들:

| 질문 | 입력 |
|---|---|
| 키 저장소 비밀번호 | **직접 정한 비밀번호** (6자 이상). 꼭 메모 |
| 이름/조직/도시 등 | 아무 값이나 가능 (개인이면 이름·`Unknown` 등). 스토어에 표시되지 않음 |
| 키 비밀번호 | 그냥 Enter(저장소 비밀번호와 동일)해도 됨 |

> ⚠️ **`android\upload-keystore.jks` 파일과 비밀번호를 반드시 백업하세요** (USB + 비밀번호 관리자 등 2곳 이상).
> 잃어버리면 **앱 업데이트를 올릴 수 없습니다.** (Play 앱 서명을 쓰면 업로드 키 분실 시 Google에 재설정 요청은 가능하지만 시간이 걸립니다.)
> 이 파일은 절대 git·메신저·클라우드 공개 폴더에 올리지 마세요.

## 2단계 · 비밀번호 파일 만들기

`android\keystore.properties.example` 을 복사해서 `android\keystore.properties` 로 만들고 값을 채웁니다.

```
storeFile=upload-keystore.jks
storePassword=(1단계에서 정한 비밀번호)
keyAlias=upload
keyPassword=(키 비밀번호. 저장소와 같게 했으면 같은 값)
```

## 3단계 · 릴리스 빌드 (AAB)

```powershell
cd C:\Users\jski1\lotto-app-build
npx cap sync android
cd android
$env:JAVA_HOME = "C:\Users\jski1\.jdks\jbr-21.0.11"
.\gradlew bundleRelease
```

결과 파일: `android\app\build\outputs\bundle\release\app-release.aab` → Play Console에 이 파일을 업로드합니다.

서명이 됐는지 확인하려면:

```powershell
& "C:\Users\jski1\.jdks\jbr-21.0.11\bin\jarsigner.exe" -verify -verbose android\app\build\outputs\bundle\release\app-release.aab | Select-String "jar verified"
```

## 4단계 · Play Console에 올릴 때

- **Play 앱 서명**(권장)에 동의하면, 방금 만든 키는 "업로드 키"가 되고 실제 배포 서명은 Google이 관리합니다.
- 새 버전을 올릴 때마다 `android/app/build.gradle`의 **`versionCode`를 1씩 올려야** 합니다 (지금 1). `versionName`은 사용자에게 보이는 이름입니다.

### 개인정보처리방침 호스팅 (URL이 있어야 Play 등록이 됩니다)

건강 앱은 Render 서버(`server/public/privacy.html`)에서 서빙합니다. 복권 앱은 서버가 없어서 정적 호스팅이면 충분합니다.

| 방법 | 특징 |
|---|---|
| **GitHub Pages** (추천) | 새 저장소 만들고 `docs/` 를 Pages 소스로 지정 → `https://<계정>.github.io/<저장소>/privacy.html`. 무료·서버 관리 불필요 |
| 건강 앱 서버에 파일 추가 | 이미 있는 Render에 `server/public/`으로 복사. 다만 **건강 앱 저장소를 건드려 재배포**가 일어나므로 비추천 |

## 참고: 광고와 복권 콘텐츠

AdMob·Play 정책은 **도박 관련 앱**에 대해 제한을 두는 경우가 있습니다. 이 앱은 복권을 팔거나 베팅을 중개하지 않는 "당첨 확인 도구"이지만,
정책 해석에 따라 광고 게재가 제한되거나 심사에서 추가 질문을 받을 수 있습니다. **AdMob에 앱을 등록한 뒤 정책 센터의 안내를 꼭 확인**하세요.
